# Parent Control

## 1. Сервер — Windows 10
1. Встановіть Python 3 з https://www.python.org/downloads/ (позначити "Add python.exe to PATH").
2. Відкрийте папку `server/windows/`, запустіть **setup.bat** (один раз) — встановить залежності й попросить придумати пароль адміністратора. (Текст у вікні консолі англійською навмисно — `cmd.exe` у Windows ненадійно обробляє кирилицю в .bat-файлах; сама веб-панель лишається українською.)
3. Запустіть **start.bat**. Скрипт покаже адресу панелі, напр. `http://192.168.1.50:8000` — саме цю адресу потрібно буде ввести в Android-додатку.
4. При першому запуску Windows Defender Firewall запитає дозвіл на з'єднання — дозволити для приватної мережі.
5. Щоб сервер працював завжди, не закривайте вікно `start.bat` (можна згорнути) або додайте `start.bat` у автозавантаження Windows (Пуск → "Виконати" → `shell:startup`, покласти туди ярлик).

Сервер використовує SQLite-файл `server/pc.db` — створюється сам, окремої бази даних ставити не потрібно.

## 2. Android-додаток — збірка APK на GitHub
У репозиторії вже є `.github/workflows/android-build.yml`.
1. Завантажте цю папку як репозиторій на GitHub (або `git push`).
2. GitHub → вкладка **Actions** → workflow «Build APK» → **Run workflow** (або він запуститься сам після push).
3. Коли збірка завершиться (зелена галочка), відкрити її → в розділі **Artifacts** завантажити `parent-control-apk` → розпакувати zip → отримати `app-debug.apk`.
4. Передати APK на дитячий телефон (посиланням, кабелем, через Google Drive) і встановити (потрібно дозволити «встановлення з невідомих джерел»).

## 3. Налаштування дитячого пристрою
1. Панель батьків (адреса з кроку 1.3) → «Додати пристрій» → отримати 6-значний код (дійсний 10 хв).
2. Відкрити встановлений додаток, ввести адресу сервера і код → «Підключити».
3. Натиснути кнопки 1–4 в додатку: доступ до статистики, служба спеціальних можливостей, адміністратор пристрою, дозвіл на мережевий фільтр (це системний запит, з'явиться один раз — без нього блокування сайтів не працюватиме, навіть якщо увімкнути його в панелі).
4. Натиснути **«5. Приховати додаток»** — іконка зникне зі списку додатків, дитина його не побачить.

### Як батьки повертають меню, коли іконку приховано
- Набрати в Телефоні (додаток для дзвінків) комбінацію: **`*#*#7273#*#*`**
- Або відкрити в будь-якому браузері посилання: **`pcadmin://open`**

### Захист від вимкнення
- Поки активні права «Адміністратор пристрою», дитина **не може видалити додаток** звичайним способом — Android спершу вимагає зняти права адміністратора в Налаштування → Безпека → «Адміністратори пристрою», а там попередження прямо написане в самому додатку.
- Якщо хтось все ж зняв права адміністратора, додаток одразу повідомляє про це сервер — у панелі біля пристрою з'явиться червоне **«⚠ захист знято на пристрої»**.
- Якщо вимкнути саму службу спеціальних можливостей (блокування додатків), пристрій перестане синхронізуватись і в панелі він почне показувати «давно не був онлайн» — це теж сигнал батькам.

### Надійніший, але складніший варіант (опційно)
Звичайні права адміністратора все одно можна зняти вручну в Налаштуваннях (з попередженням). Щоб зробити це практично неможливим без скидання телефону до заводських налаштувань, можна зробити додаток **власником пристрою (Device Owner)** — це робиться один раз через USB на ще не налаштованому (або щойно скинутому) телефоні, без жодного Google-акаунту:
```
adb shell dpm set-device-owner ua.parentcontrol.agent/.AdminReceiver
```
Якщо на телефоні вже є акаунти, спочатку потрібне скидання до заводських налаштувань. Це вже рівень Google Family Link — за потреби можу додати відповідний код.

## Можливості

**Повне блокування пристрою.** Кнопка «Заблокувати пристрій» у панелі, а також автоматично при вичерпанні **денного** ліміту часу — у обох випадках три незалежні механізми тримають екран заблокованим: (1) миттєва реакція на подію розблокування (`ACTION_USER_PRESENT`) із невеликою затримкою 300 мс; (2) окремий цикл перевірки кожні ~2 секунди, що блокує екран знову незалежно від того, чи спрацювала подія, — головний «запобіжник», бо на деяких виробниках (Samsung, Xiaomi тощо) система може затримувати широкомовні сповіщення через оптимізацію батареї; (3) блокування й при будь-якій спробі показати інтерфейс через службу спеціальних можливостей. Розблокувати пристрій звичайним шляхом по суті неможливо — він повертається в заблокований стан щонайбільше за пару секунд. Блокування через денний ліміт саме скидається опівночі, коли рахунок використання починається заново. Чесно попереджаю: усе це працює, лише поки активна служба спеціальних можливостей.

**Блокування/ліміт одного додатка.** Якщо заблоковано лише конкретний додаток, вичерпано його особистий ліміт, або зараз тихі години (а додаток не у списку дозволених) — пристрій показує власний повноекранний екран «Додаток заблоковано» і за ~1 секунду переходить на домашній екран. Це надійніша заміна старому підходу (просто «натиснути HOME»), чия поведінка залежала від конкретного лаунчера на пристрої — тепер вона однакова на будь-якому телефоні. У тихі години додатки зі списку «дозволені під час тихих годин» (наприклад, дзвінки) лишаються доступні — блокуються лише решта.

**Звітність.** На сторінці пристрою — картка «Звітність» із перемикачем **День / Тиждень / Місяць** і стрілками ← → для гортання періодів назад (вперед — не далі поточного). Статистика береться напряму з історії використання, тому коректно показує дані за будь-який минулий день, навіть якщо додаток із того часу перейменували чи видалили з пристрою. Керування (блокування/ліміт додатка) активне лише на вкладці «День» за сьогодні — для минулих періодів це просто довідкова статистика.

**Ліхтарик і сигнал тривоги.** Дві кнопки на сторінці пристрою — вмикають спалах камери або голосний звук на максимальній гучності (навіть якщо пристрій на беззвучному режимі) на ~25 секунд, класична функція «знайти телефон». Виконується протягом ~20 секунд після наступної синхронізації.

**Прослуховування мікрофону я не реалізовував і не реалізовуватиму** — технічно це приховане аудіо-стеження за дитиною й за будь-ким, хто з нею в той момент розмовляє (а ця інша людина на запис не погоджувалась), і в більшості юрисдикцій, включно з Україною, підпадає під окреме законодавство про таємницю переговорів.

**Фільтр сайтів (блокування соцмереж незалежно від того, яким додатком їх відкрили).** Секція «Фільтр сайтів» на сторінці пристрою: перемикач-вимикач (за замовчуванням вимкнено) і список заблокованих доменів (за замовчуванням порожній, батьки додають самі; базовий список можна задати й у шаблоні).
- Працює як невеликий локальний VPN **лише для DNS**-трафіку (порт 53) — навмисно вузько налаштований: маршрути ведуть тільки до конкретних IP-адрес DNS-серверів пристрою, а не до всього трафіку (`0.0.0.0/0`). Це свідомий вибір заради безпеки: навіть якщо в коді є помилка, під загрозою лише розпізнавання доменних імен (сайт може не відкритись), а не з'єднання пристрою з інтернетом загалом.
- **Відомий пробіл:** не діє на Chrome, якщо в ньому увімкнено «Безпечний DNS» (DNS-over-HTTPS, типово увімкнено за замовчуванням) — такі запити взагалі не йдуть через порт 53, і фільтр їх не бачить. Звичайні додатки соцмереж (Instagram, TikTok, Facebook тощо) зазвичай користуються системним DNS і під фільтр підпадають.
- **Я не мав змоги це протестувати** — у середовищі, де це писалося, немає Android-пристрою чи емулятора, лише статичний перегляд коду. Обов'язково перевір на своєму пристрої кілька днів, перш ніж покладатися на це з дитячим телефоном. Перемикач у панелі — аварійний вимикач: вимикає фільтр на пристрої протягом ~20 секунд після наступної синхронізації.

**Оновлення додатку через сервер.** Сторінка «Оновлення додатку» в панелі: завантажте новий APK (зібраний через GitHub Actions, див. вище) разом із номером версії — підключені пристрої самі завантажать і встановлять його протягом ~20 секунд після наступної синхронізації.
- *Важливо:* перед кожним новим релізом підніміть `versionCode` у `android/app/build.gradle.kts` (зараз 3) — інакше пристрої не побачать, що є новіша версія.
- У репозиторії є `android/keystore/debug.keystore` — фіксований ключ підпису, однаковий для всіх збірок. Без нього кожна збірка підписувалась би новим випадковим ключем, і Android вимагав би спершу видалити старий додаток замість оновлення поверх нього.
- Без Device Owner Android все одно один раз попросить дитину торкнутися «Встановити» в системному діалозі — публічного API для повністю беззвучного оновлення звичайного додатка в Android немає.

**Трекер (геолокація).** Крок «5. Геолокація» в додатку (натиснути двічі: спершу точна геолокація, потім дозвіл працювати у фоні). На сторінці пристрою — картка «Місцезнаходження» з останньою відомою точкою і посиланням «Відкрити на карті». Це пасивне читання (без активного запиту GPS, щоб менше садити батарею) — тому може бути застарілим, якщо на пристрої довго ніхто не користувався геолокацією. Історії переміщень поки немає, лише остання відома точка — якщо потрібен трек/маршрут за день, можу додати окремо.

**Облік трафіку — виправлено.** Перша версія використовувала `TrafficStats.getUidRxBytes/getUidTxBytes`, які для **чужих** застосунків на сучасному Android часто мовчки повертають «непідтримується» — тому все показувало нулі. Переписано на `NetworkStatsManager`, який офіційно призначений саме для цього і використовує той самий дозвіл «Доступ до статистики використання», що вже й так запитується в кроці 1 (нічого додатково дозволяти не треба).

**Діагностика фільтра сайтів.** На сторінці «Фільтр сайтів» тепер видно для кожного пристрою: чи надано дозвіл на VPN, чи фільтр зараз активний, і якщо ні — чому саме (текст помилки з пристрою). Найчастіша причина «не працює» — не виконаний на пристрої пункт 4 (одноразове підтвердження системного запиту на VPN); без нього перемикач у панелі нічого не вмикає.

## Аудит (три скарги: «керування лише при активному екрані», «оновлення не працює», «блокування хостів не працює»)

**1. Керування лише при активному екрані.** Найімовірніша причина — Android «Doze»: коли екран вимкнений і пристрій лежить нерухомо, система відкладає мережеві операції фонових застосунків, поки екран знову не увімкнуть. Додав крок **«6. Вимкнути оптимізацію батареї»** в додатку — без нього це очікувана поведінка Android, а не помилка коду. Статус тепер видно і в самому додатку.

**2. Оновлення не працювало — знайшов дві реальні помилки:**
- `InstallReceiver` обробляв лише «потрібне підтвердження користувача» — якщо встановлення провалювалось з будь-якої іншої причини (конфлікт підпису, нестача місця тощо), ми про це взагалі не дізнавались. Тепер фіксується кожен можливий результат.
- `Updater` позначав версію як «вже спробовану» одразу після того, як запит на встановлення пішов — і якщо встановлення після цього мовчки не відбувалось, повторної спроби для цієї версії більше ніколи не було. Тепер повторює спробу кожні 30 хв, поки версія дійсно не встановиться.
- Результат («встановлено», «помилка: ...», «очікує підтвердження») видно в панелі на сторінці пристрою.
- **Нерозв'язана підозра, чесно:** на звичайному (не Device Owner) пристрої системний діалог підтвердження запускається з `BroadcastReceiver`, без власного Activity на передньому плані — на Android 10+ це потрапляє під обмеження фонового запуску екранів і теоретично може мовчки не спрацювати. Якщо після цих правок статус і далі зависає на «очікує підтвердження» — це практично напевно воно, і єдине повне вирішення — режим Device Owner (описаний нижче), де підтвердження не потрібне в принципі.

**3. Блокування хостів — знайшов реальний дефект продуктивності:** пересилання звичайних (недозаблокованих) DNS-запитів на справжній сервер виконувалось синхронно в тому самому потоці, що читає нові пакети з VPN-інтерфейсу — під час очікування відповіді (до 4 с) усі інші запити застрягали в черзі. При завантаженні однієї сторінки, яка робить десятки DNS-запитів одразу, це могло виглядати як «не працює». Виніс пересилання в пул потоків, щоб читання не зупинялось. Також посилив визначення IPv4 DNS-серверів пристрою (було на основі підрахунку крапок у рядку, тепер — коректна перевірка типу адреси).

Усе це я **не міг перевірити на реальному пристрої чи мережі** — лише вичитування коду. Якщо після оновлення (versionCode 7) проблема лишається, діагностичні повідомлення в панелі (на сторінках пристрою та «Фільтр сайтів») тепер мають показати куди саме дивитись.

## Безпека / прод
- Під локальну Wi-Fi мережу вдома HTTP достатньо. Якщо сервер буде доступний із зовнішнього інтернету — обов'язково HTTPS (наприклад, через безкоштовний Cloudflare Tunnel або reverse-proxy з Let's Encrypt) і прибрати `usesCleartextTraffic` з Android-маніфесту.
- Пароль ADMIN_KEY зберігається лише в `config.bat` на вашому комп'ютері — нікому не передавайте цей файл.
